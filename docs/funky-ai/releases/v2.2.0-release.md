# 🚀 Funky AI v2.2.0 Release Notes

## 🌟 Resumen de la Versión
La versión **v2.2.0** introduce el soporte nativo para **Entornos de Ejecución Sensibles (Environment-Aware Scaffolding)** en el comando `funky init`. Esta feature separa de manera estricta las reglas y protocolos necesarios para un desarrollo interactivo basado en disco local (**IDE**) de las optimizaciones necesarias para dispatch de subagentes asíncronos en background (**CLI**).

Esta arquitectura modular soluciona la asimetría operativa y el sobreescribido no intencional de plantillas (el *LLM Overwrite Trap*), proveyendo al usuario un selector interactivo amigable al inicializar su ecosistema y garantizando al mismo tiempo un modo *Headless* determinista y retrocompatible para procesos de integración continua (CI) y repositorios preexistentes.

### ✨ Nuevas Funcionalidades y Refactor
- **Selector de Entorno Interactivo (IDE vs CLI):** Añadido selector interactivo mediante `@clack/prompts` para elegir el entorno de ejecución objetivo.
- **Ruteo Dinámico de Templates:** La función `runInit` copia dinámicamente las reglas del agente (`engram-protocol.md` y `sdd-orchestrator.md`) desde carpetas independientes `bootstrap/ide/` o `bootstrap/cli/` basándose en la selección.
- **Guardrail de No-Interactividad (Headless Fallback):** Detección robusta de TTY y presencia de canvas previos para fallback directo al entorno `'ide'`, evitando terminales bloqueadas en pipelines de CI/CD.
- **Actualización de Documentación Viva:** Documentados los nuevos escenarios interactivos y árboles de decisión en `funky-init-flow.md`, `escenarios-de-uso.md`, y el `README.md` del CLI.

### 🛠️ Archivos Modificados
- **`funky-cli/src/commands/init.js`:** Inyección de prompt interactivo `p.select`, guardrails de no-interactividad y ruteo dinámico de plantillas estáticas.
- **`funky-cli/tests/init.test.js`:** Agregadas pruebas unitarias sólidas para verificar la correcta resolución de rutas para entornos `IDE`, `CLI`, y comportamiento retrocompatible default `'ide'`.
- **`funky-cli/src/templates/bootstrap/`:** Creación de las subcarpetas `ide/` y `cli/` y movimiento/mutación de las reglas correspondientes.
- **`docs/funky-ai/operaciones/funky-init-flow.md`:** Actualizado con el nuevo árbol de decisión y mapeo dinámico.
- **`docs/funky-ai/operaciones/escenarios-de-uso.md`:** Añadida la guía para interactuar con el prompt en el Escenario 2.
- **`funky-cli/README.md`:** Reflejado el cambio del comando y la estructura física de directorios generada.

### 🔒 Guardrails Preservados
- **Retrocompatibilidad Absoluta:** Si no se especifica el entorno, la función `runInit` asume de forma inalterable `'ide'`, asegurando que todos los tests históricos de integración y setups sigan funcionando.
- **Protección de Canvas:** El modo Headless preserva intactos `PROJECT-CANVAS.md` e `INFRA-CANVAS.md`, limitándose a inyectar las reglas faltantes de manera idempotente.

### 🧠 Aprendizajes (Engram)
- **`[llm-overwrite-trap]`:** Descubrimiento crítico acerca de la tendencia natural de los LLMs a preferir sobreescrituras en bloque (`write_to_file`) en lugar de ediciones quirúrgicas (`replace_file_content`). Mitigado implementando Action Forcing Rules en la plantilla del Orquestador de CLI.
- **`[tty-headless-prompt-guardrail]`:** Los prompts interactivos pueden congelar procesos automatizados que no disponen de una terminal interactiva (TTY). La verificación previa de archivos clave actua como el guardián óptimo para asumir fallbacks deterministas de forma segura.
