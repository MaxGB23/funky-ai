# 🚀 Funky AI v4.3.0 Release Notes

## 🌟 Resumen de la Versión
MINOR release centrada en el **brief funcional como artefacto de primer nivel** del pipeline funky-forge: `funky init` pasó a generar `brief-funcional.md` como **primer output** (antes de los canvases), y `funky estimate` ahora lo **auto-detecta** si no se le pasa `--brief` — la sesión de estimación consume las decisiones del brief sin fricción (issue #33, PR #34).

En paralelo se cerró la **deuda de pruebas y docs**: el contrato de documentación R9 de `init.md` quedó protegido con un test real-file, y `funky-init-flow.md` + el README se realinearon con el CLI real (diagrama `runInit`, 4 outputs estáticos, sin referencias muertas). También se corrigió un **bug silencioso en la suite**: 25 llamadas a `parse(['node', 'assess'/'estimate'], {from:'user'})` pasaban el nombre del comando como argumento con commander 15, generando ruido `too many arguments` en cada corrida — el verify-report #342 lo había etiquetado como "drift de lockfile", pero era un defecto real de los tests.

### ✨ Nuevas Funcionalidades y Refactor
- **[Feature] Brief funcional como primer output de `funky init`:** el scaffold ahora copia `brief-funcional.md` antes de los canvases, y el texto de ayuda lo declara explícitamente.
- **[Feature] Auto-detección del brief en `funky estimate` (`R-E2`):** si no se pasa `--brief`, `funky estimate` busca `brief-funcional.md` en el directorio; si lo encuentra, lo embebe en `pricing-guide.md` y avisa con el log 💡 "Brief funcional detectado". Fallback al flujo anterior si no existe.
- **[Test] Contrato de docs R9 protegido:** `tests/init.test.js` lee el `init.md` real y verifica que el brief sea el primer output y que el diagrama mencione `runInit`/`copy brief-funcional.md` — rompe si los docs se desalinean del CLI.
- **[Fix] Ruido `too many arguments` eliminado de la suite:** `parse(['node', 'assess'], {from:'user'})` → `parse([])` (o solo flags) en `assess.test.js` y `estimate.test.js`; con `from:'user'`, commander 15 interpreta el array como argumentos puros de usuario.

### 🧠 Aprendizajes (Engram)
- **`[commander-parse-from-user]`:** Con `{from:'user'}`, commander 15 espera SOLO los argumentos de usuario en el array — nunca `'node'` ni el nombre del comando. El patrón correcto para comandos hoja sin operands es `parse([])`; los subcomandos (pipeline) sí pasan el nombre.
- **`[verify-drift-vs-real-bug]`:** Un verify-report puede etiquetar ruido de suite como "drift pre-existente" cuando el síntoma aparece con versiones correctas — vale la pena reproducir con el lockfile real antes de archivar un bug.
- **`[brief-auto-detect]`:** La auto-detección por convención de nombre (`brief-funcional.md`) reduce fricción de la sesión sin romper el flujo explícito; el log 💡 da visibilidad de cuál fuente se usó.
