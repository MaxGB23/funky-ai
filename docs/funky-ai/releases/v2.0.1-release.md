# 🚀 Funky AI v2.0.1 Release Notes

## 🌟 Resumen de la Versión

La v2.0.1 es un **parche arquitectónico crítico** que corrige una regresión detectada post-lanzamiento de v2.0.0: la **Asimetría Operativa**. El Orquestador había sido migrado a la Capa 3 (Workflows On-Demand) junto al Worker, lo que provocaba *Context Fading* severo en sesiones largas de planificación. El modelo "olvidaba" su rol a medida que el historial de chat crecía.

El fix reestablece la separación correcta: el **Orquestador vive en la Capa 2** (Workspace Rules, inyectado por el IDE en el System Prompt, persistente) y el **Worker sigue en la Capa 3** (Slash Command, efímero, para ejecuciones atómicas). Esta distinción es irreversible y está ahora formalizada en la documentación oficial.

Además, se recuperó la **Feature 012 (Auto-Tiering)** — la Escalation Matrix y el Paso 0 (Razonamiento Pre-Vuelo) — que se habían perdido silenciosamente en la migración a v2.0.0 (*Doc Rot*).

---

### ✨ Cambios Principales

- **Fix: Context Fading del Orquestador** — El Orquestador vuelve a la Capa 2 (`.agents/rules/sdd-orchestrator.md` con `trigger: model_decision`). Ya no se inyecta por chat, sino por el System Prompt del IDE.
- **Rescue: Feature 012 (Auto-Tiering)** — Se recuperó la *Escalation Matrix* (T1/T2/T3) y el "Paso 0 — Razonamiento Pre-Vuelo" que el Orquestador debe ejecutar antes de generar cualquier artefacto.
- **Fix: Session Close Protocol** — Se agregó referencia explícita a `.agents/rules/engram-protocol.md` en la sección Session Close del Orquestador.
- **Cleanup: Naming de Rules** — Se eliminó el archivo `.agents/rules/sdd-orchestrator-core.md` (legacy confuso). Un solo nombre: `sdd-orchestrator.md`.
- **Fix: Template CLI Sincronizado** — `funky-cli/src/templates/bootstrap/agents-rules-sdd-orchestrator.md` actualizado con el template validado en sandbox.
- **Fix: Stale-Ref** — `docs/funky-ai/guias/comando-vs-archivos.md` actualizado: `orchestrator-core.md` → `sdd-orchestrator.md`.

### 🧠 Aprendizajes (Engram)

- **`[system-prompt-vs-chat-history]`** — Rules de larga duración (Orquestador) van en Capa 2 (System Prompt). Slash Commands son para ejecución efímera (Worker). Nunca meter un rol de larga duración en un Slash Command.
- **`[orchestrator-context-overload]`** — La solución al Context Overload no es añadir texto, es estructurar las reglas por capas.
