# 🚀 Funky AI v4.5.0 Release Notes

## 🌟 Resumen de la Versión
MINOR release centrado en el **rename `funky scaffold` → `funky sdd install` (fase 1) y el nuevo `funky scaffold` agnóstico openspec/sdd (fase 2, PR #38)**: el comando canónico para instalar el framework completo pasa a vivir bajo el namespace `funky sdd install`, y `funky scaffold` deja de ser un alias deprecado para convertirse en un comando real y ligero que instala **exactamente 4 archivos** (README interpolado, ORCHESTRATOR-STATE, `release-notes.md` y `000-rfc-template.md`), funcionando tanto para instalaciones openspec como sdd.

La release agrupa el trabajo del PR #38 (merge `b4353ca`) más 4 commits de post-merge: 2 de docs sync (`af6d130`, `8c7924d`) y 2 de organización de drafts de smoke tests (`b31050a`, `92f4545`).

### ✨ Nuevas Funcionalidades y Refactor
- **[Feat] `funky sdd install` canónico (fase 1):** el nombre canónico del framework completo es ahora `funky sdd install` (namespace `sdd` + subcomando `install`); `funky scaffold` conserva la instalación completa como alias durante la transición.
- **[Feat] `funky scaffold` agnóstico (fase 2):** comando real e idempotente que instala solo 4 archivos (README con `{{project_name}}` interpolado, ORCHESTRATOR-STATE como hub, `release-notes.md`→`.agents/templates/sdd/`, `000-rfc-template.md`→`openspec/rfcs/`), sin deprecación ni warning — ya no instala el ecosistema completo.
- **[Docs] README base generalizado:** el template compartido con `sdd install` usa ORCHESTRATOR-STATE como hub (sin canvas/engram como puntos centrales).
- **[Docs] Scaffold.md re-creado:** documentación del comando agnóstico re-creada y registrada en el SSOT (`docs-live-index`) con índice seccional propio.
- **[Docs] Alineación de referencias:** docs e índices que apuntaban a `scaffold` como instalador completo alineados con `sdd install`; sin residuos vivos de "alias deprecado".

### 🧠 Aprendizajes (Engram)
- El rename scaffold→sdd install + scaffold agnóstico mantiene ambos contratos: `funky sdd install` instala el framework completo y `funky scaffold` instala solo 4 archivos base idempotente.
- `scaffold.md` re-creado en la fase 2 requirió registro posterior en el SSOT (`docs-live-index`) + índice seccional — el flujo docs sync post-merge lo detectó y cerró.
- El `--help` del CLI inyecta el doc vía `addHelpText('after')` (`enrichCommandHelp`), así que doc y help son idénticos por construcción: verificar comportamiento real (archivos creados) además de superficie.
