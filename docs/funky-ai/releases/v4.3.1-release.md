# 🚀 Funky AI v4.3.1 Release Notes

## 🌟 Resumen de la Versión
PATCH release de **refactor interno de la organización de tests**: la suite de `funky-cli` pasó de un archivo de 1,474 líneas que mezclaba tres unidades bajo prueba a una estructura por unidad, con convención documentada y enforcement automático.

El criterio que guió el refactor: *si dentro de tus líneas puedes decir "estas prueban X, estas prueban Y y estas prueban Z", probablemente deberías separarlas*. `estimate.test.js` cumplía exactamente el criterio — mezclaba el dominio de templates, el clasificador de señales y el CLI de estimación. La suite ahora está organizada por cohesión, con un meta-test (`organization.test.js`) que corre con `pnpm test` y falla si un unit test mezcla módulos de comando o supera los topes por tipo de archivo. La deuda legacy existente se migró y el mapa de excepciones quedó vacío.

### ✨ Nuevas Funcionalidades y Refactor
- **[Refactor] `estimate.test.js` (1,474 líneas) partido en 4 archivos por unidad bajo prueba:** `estimateDomain.test.js` (funciones puras de templates), `estimateTopics.test.js` (clasificador de señales), `estimateCommand.integration.test.js` (flujo + `--context`) y `estimateCommand.flags.integration.test.js` (flags R7–R14 y auto-detección de brief #33). Contenido movido byte-por-byte.
- **[Refactor] Helper compartido de mocks fs:** `tests/helpers/fsMock.js` elimina el bloque `sharedFsMock`/`vi.mock` duplicado (estaba en `estimate`, `assess` e `init`); `assess.test.js` y los nuevos archivos importan del helper.
- **[Enforcement] Meta-test `organization.test.js`:** corre con `pnpm test`. Reglas: unit ≤ 500 líneas, integration ≤ 800, y cohesión — un unit test importa de a lo sumo UN módulo de `src/commands/` (dos o más = integración o unidad mixta → rename a `.integration.test.js` o split). Deuda legacy en `LEGACY_EXCEPTIONS` con auto-limpiado; tras la migración, vacío.
- **[Refactor] Migración de deuda legacy:** `pipeline.test.js` renombrado a `pipeline.integration.test.js` (prueba el flujo completo con dependencias mockeadas); `assess.test.js` partido (555→481) con `assessFrontmatter.test.js` para `parseFrontmatter` puro; `context.test.js` 505→473 con helpers movidos a `tests/helpers/contextHelpers.js`; `skills.test.js` importa solo `commands/skills.js` (el test de paridad R-SK-5 se eliminó por redundancia: cubierto por `scaffold.test.js` y `scaffold.integration.test.js`).
- **[Convención] Skill `vitest` con sección "Repo conventions (funky-ai)"** para que los sub-agentes escriban tests nuevos conforme a la convención; `AGENTS.md` recortado de 33 a 26 líneas (padding eliminado, intención intacta).

### 🧠 Aprendizajes (Engram)
- **`[test-cohesion-criterion]`:** Si en un archivo de tests puedes decir "estas 400 líneas prueban X, estas 300 prueban Y", separa. El número no es el criterio — la cohesión (un archivo = una unidad bajo prueba) lo es.
- **`[enforcement-location]`:** La convención de escritura va donde trabaja el escritor (skill que cargan los sub-agentes), no en el contexto que el orquestador paga en cada request (`AGENTS.md`). La prueba de fuego: ¿quién ejecuta la regla — el orquestador o un sub-agente bajo demanda?
- **`[skill-registry-sdd-gap]`:** El skill registry (`.atl/skill-registry.md`) NO indexa skills `sdd-*` — son agentes de fase nativos del runtime o se resuelven por system prompt, no por el índice. Las rutas de `sdd-docs-sync`/`sdd-release` en `AGENTS.md` no son redundantes.
- **`[proxy-rule-calibration]`:** La regla "unit no importa de `src/commands/`" era un proxy mal calibrado: los unit tests de módulo de comando con fs mockeado son legítimos. La regla correcta es cohesión (a lo sumo UN módulo de commands por unit test).
