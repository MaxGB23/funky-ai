# 🚀 Funky AI v4.4.0 Release Notes

## 🌟 Resumen de la Versión
MINOR release centrado en el **refactor completo de `funky estimate` (M1-M12, PR #36)**: `funky estimate` ahora es un flujo de **3 fases estrictas** con contexto unificado entre fases, tabla base de tarifas por rol siempre presente (enriquecible con `--pricing-team`), avisos con **comando correctivo** (`funky init`/`funky assess`) cuando faltan inputs, y summary con **estado por archivo** — cada guía generada informa si se escribió, se omitió o quedó pendiente. Además incluye la **tabla de costo operativo mensual** en las decisiones de pricing (M12), pregunta opcional de costo del problema en `funky init` (M9), y una pasada de **docs sync** posterior al merge para alinear `funky-forge`/`funky-ai`/SSOT con el CLI real.

La release agrupa el trabajo del PR #36 (feature estimate M1-M12, merge `18341fe`) más 3 commits de docs sync post-merge (`c3679f1`, `555a1ff`, `63ec8df`).

### ✨ Nuevas Funcionalidades y Fixes
- **[Feat] Flujo de 3 fases estrictas (M1-M3):** `funky estimate` corre con fases delimitadas (contexto unificado), sin `--brief` en la tabla de flags — el brief funcional se auto-detecta desde `funky init` o se solicita en el flujo.
- **[Feat] Tarifas base SIEMPRE en la guía (M5):** la guía de pricing incluye la tabla base de tarifas por rol por defecto; `--pricing-team` la enriquece con el equipo propio.
- **[Fix] Avisos correctivos (M6/M7/M11):** cuando no hay brief ni `--brief`, `funky estimate` avisa con el comando correctivo (`funky init`); el summary por archivo refleja estado real (escrito/omitido/pendiente) sin sobrevender omisiones.
- **[Feat] Summary con estado por archivo (M10):** `init`/`assess`/`estimate` reportan el estado de cada guía generada, con título sin sobreventa de omisiones.
- **[Feat] Tabla de costo operativo mensual (M12):** las decisiones de pricing incluyen la tabla de costo operativo mensual estimado (`f9558ef`).
- **[Feat] Costo del problema en init (M9):** `funky init` pregunta opcionalmente el costo del problema para el cliente en el brief.
- **[Refactor] Pricing-guide aditiva (fase 2):** la guía de pricing funciona como guía aditiva con marcadores; Y/N como advertencia de pérdida; sin pares de marcadores vacíos en la zona de topics (M4).
- **[Test] Naming behavior-first:** tests renombrados por comportamiento, no implementación (regla `vitest`).
- **[Chore] `.gitattributes` con LF canónico** para lockfiles.
- **[Docs] Docs sync post-merge:** `docs/funky-forge/estimate.md`, `init.md`, `assess.md` alineados con el CLI real; `init.md` registrado en el SSOT con índices actualizados; descripciones de `init`/`assess`/`estimate` en `docs(cli)` coherentes con el CLI.
