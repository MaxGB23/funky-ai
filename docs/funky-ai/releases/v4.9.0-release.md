# 🚀 funky-ai v4.9.0 Release Notes

## 🌟 Resumen de la Versión

Esta versión endurece la **puerta de entrada del framework SDD**: el Paso 0 del orquestador ahora abre con una clasificación binaria de sesión (ideación vs. implementación) hecha por el humano, cerrando el modo de falla donde una mala inferencia del modelo enviaba la sesión a chat conversacional sin que ningún checkpoint humano lo corrigiera. La respuesta del humano es vinculante para la determinación de Tier, y `sdd-preflight` pasa a ser subrutina manual del orquestador — única puerta de entrada, sin disparos autónomos.

En paralelo, se consolidó la capa metodológica (`tasks-tdd.md` eliminado, sus reglas viven ahora como entrada inyectable en `metodologias.md`) y se validó el framework completo end-to-end con un feature real archivado como evidencia histórica.

### ✨ Nuevas Funcionalidades y Refactor
- **[Session Gate binario]:** Paso 0 reordenado en pipeline bloqueante de 4 pasos: [1] pregunta ideación/implementación → [2] matriz de escalación con respuesta humana VINCULANTE (ideación siempre T0) → [3] evaluación pre-vuelo → [4] cacheo de metodologías.
- **[Preflight como subrutina]:** `sdd-preflight.md` cambia de `model_decision` a `manual`, con check CORE que obliga a leer `sdd-orchestrator.md` primero. Las keywords de activación migraron a la descripción del orquestador.
- **[POST-CONFIRMACIÓN reforzada]:** al confirmar Tier, metodologías y router se cargan en ese orden exacto, mismo turno — doble anclaje con el paso [4].
- **[Agente sdd-docs-sync]:** subagente custom con permisos acotados, prompt vía `{file}`, ya validado en flujo real delegado.
- **[Metodologías data-driven]:** reglas de estructura TDD de tasks migradas de template muerto a entrada inyectable `[tasks]` en `metodologias.md` (el tag apunta a la fase que produce la decisión).

### 🛠️ Archivos Modificados
- **`.agents/rules/sdd-orchestrator.md`:** Paso 0 binario + tier vinculante (+ mirror sincronizado byte a byte).
- **`.agents/rules/sdd-preflight.md`:** trigger manual, check CORE, tabla de sesión con `metodologias_activas`, POST-CONFIRMACIÓN ordenada (+ mirror).
- **`.agents/rules/metodologias.md`:** nueva entrada "Estructura TDD de tasks" `[tasks]`.
- **`.agents/templates/sdd/tasks-tdd.md`:** eliminado (cero referencias).
- **`docs/funky-ai/prompts/globals/funky-global-chilango.md`:** Workspace Bootstrap solo lee `ORCHESTRATOR-STATE.md` bajo instrucción explícita o continuación de roadmap.
- **`docs/funky-ai/conceptos/orquestador-sdd.md` + `sdd.md` + índice seccional:** docs-sync alineado al flujo nuevo.
- **`openspec/archive/arbol-navidad-cli/`:** evidencia del primer test end-to-end exitoso del framework.

### 🔒 Guardrails Preservados
- Anti-Router-Prematuro JIT intacto (routers solo tras confirmación de Tier).
- Paridad byte-a-byte de mirrors verificados (SHA256) en docs-sync.
- Work unit commits por decisión lógica; sin atribución AI.

### 🧠 Aprendizajes (Engram)
- **`{file}` prompts freeze at startup:** la inyección de prompt de agentes custom resuelve una sola vez al arrancar OpenCode, no por launch.
- **Layering rule:** el método del agente vive en su skill, no en AGENTS.md.
- **Tag = fase productora:** las entradas de metodologías se taguean según quién genera la decisión, no quién la consume.
