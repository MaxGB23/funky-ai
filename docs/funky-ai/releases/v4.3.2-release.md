# 🚀 Funky AI v4.3.2 Release Notes

## 🌟 Resumen de la Versión
PATCH release centrado en **`funky skills`**: el instalador ahora carga los manifests de las skills de forma **dinámica**, cerrando el bug por el que una skill nueva detectada en `src/skills/` (p. ej. una carpeta de prueba) aparecía en la selección pero **no se instalaba** (reporte de usuario: "0 creados"). Además se corrige la superficie del CLI y se refina la convención de organización de tests.

El origen del bug: `runSkills` usaba una lista `MANIFESTS` hardcodeada (solo `sdd-release` y `sdd-docs-sync`), mientras que `discoverSkills` ya detectaba cualquier skill con `SKILL.md` + `manifest.js`. La detección y la instalación iban por caminos distintos — la skill aparecía en el menú pero no era instalable. Ahora la acción interactiva importa el `manifest.js` de cada skill seleccionada en tiempo de ejecución: **cualquier skill nueva queda instalable sin tocar código** (R-SK-8).

### ✨ Nuevas Funcionalidades y Fixes
- **[Fix] Manifests dinámicos por skill (R-SK-8):** `runSkills` deja de usar la lista hardcodeada. La acción carga `manifest.js` de cada skill seleccionada con `await import(pathToFileURL(...))`. Una skill nueva con `SKILL.md` + `manifest.js` es detectable (R-SK-7) e instalable desde el primer momento.
- **[Fix] `--help` genérico:** la descripción del comando hardcodeaba `(sdd-release, sdd-docs-sync)`, contradiciendo el comportamiento dinámico — detectado por la verificación de superficie de docs-sync. Ahora describe "las skills detectadas bajo `src/skills/`".
- **[Fix] Autodetección estricta (R-SK-7):** `discoverSkills` exige `SKILL.md` **y** `manifest.js` con nombre exacto (case-sensitive incluso en NTFS: `skill.md` en minúsculas no cuenta). Un directorio sin manifest no aparece como skill instalable.
- **[Refactor] Selección única (`select`):** el instalador usa menú de selección única (`select`) con **Todas** o una skill específica; no existe selección vacía — cancelar (Esc/Ctrl+C) sale con código 1 sin realizar cambios (R-SK-6).
- **[Convención] Categoría `.interactive.test.js`:** documentada en la skill `vitest` como tercera categoría aceptada (harness con I/O real de prompts, exenta de la regla de 1 import como las integration) y aplicada en `organization.test.js` (`isIntegration` incluye `.interactive.test.js`); `AGENTS.md` agrega el disparador para cargar la skill al tocar tests de funky-cli.
- **[Test] Regresión R-SK-8:** skill nueva con manifest propio produce sus intenciones sin hardcode; el test `__all__` deriva expectativas de la detección real (instala todas las skills detectadas y sus recursos).

### 🧠 Aprendizajes (Engram)
- **`[manifest-list-static-vs-discovery]`:** La causa del "0 creados" fue una lista de manifests hardcodeada mientras la detección era dinámica — detección e instalación por caminos distintos. El manifest por skill debe ser la ÚNICA fuente de recursos (R-SK-8), cargado en tiempo de instalación.
- **`[powershell-utf8-corruption]`:** `Set-Content -Encoding UTF8` de PowerShell 5.1 corrompe archivos UTF-8 con acentos/emojis al roundtripear con `Get-Content -Raw` (mojibake). Nunca reescribir archivos con caracteres no-ASCII vía PowerShell; usar herramientas de edición.
- **`[orchestrator-skill-trigger]`:** El orquestador en ruta inline no carga skills de sub-agente por defecto; un disparador condicional en `AGENTS.md` (la capa siempre-cargada) hace el self-check determinista sin duplicar la regla completa (que vive en la skill bajo demanda).
