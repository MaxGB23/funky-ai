# 🚀 Funky AI v1.10.0 Release Notes

## 🌟 Resumen de la Versión
Esta versión (v1.10.0) introduce la automatización de la Fase 0 y el nuevo comando `funky release`. Su objetivo principal es reducir la fricción manual en la creación de ramas de git y estandarizar la generación de Release Notes y READMEs, eliminando tareas repetitivas para el orquestador y los workers.

### ✨ Nuevas Funcionalidades y Refactor
- **[Feature] Comando `funky release`:** Nuevo comando CLI que genera automáticamente las release notes de la versión utilizando templates canónicos, previniendo errores humanos y asegurando la coherencia.
- **[Feature] Automatización Fase 0:** Se refactorizaron las tareas (`tasks.md`) para que la configuración inicial del branch en Git pase de ser una tarea manual del Humano a ser un proceso ejecutable por un Worker Tier 1.
- **[Refactor] Auditoría de Templates:** Se auditaron y unificaron los templates de release y README para mantenerlos pragmáticos, eliminando la "burocracia inútil" y sincronizándolos en el CLI.

### 🛠️ Archivos Modificados
- **`funky-cli/src/templates/sdd/tasks.md`:** Refactorizada la Fase 0 para ser Worker-friendly.
- **`funky-cli/src/commands/release.js`:** Nueva lógica para el comando de release.
- **`funky-cli/funky.js`:** Registro del comando de release.
- **`funky-cli/src/templates/release.md` y `README.md`:** Nuevos templates canónicos y sincronizados.
- **`README.md`:** Actualizado con el mapa de navegación v1.10.0.

### 🔒 Guardrails Preservados
- Se mantuvieron los protocolos y el Tier system en `tasks.md`.
- El comando `release` es idempotente, previene la sobreescritura accidental.

### 🧠 Aprendizajes (Engram)
- **`[template-audit-pragmatism]`:** La consolidación de templates revela que pedir datos exhaustivos causa fatiga; los golden paths y ejemplos concretos son más efectivos que las estructuras teóricas complejas.
