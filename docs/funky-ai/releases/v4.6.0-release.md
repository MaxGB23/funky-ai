# 🚀 Funky AI v4.6.0 Release Notes

## 🌟 Resumen de la Versión
MINOR release que convierte el estándar de hardening de dependencias pnpm del RFC `feature-secure.md` en CLI operativo con la **primera entrega de `funky secure`**: tres subcomandos — `doctor` (diagnóstico conductual, solo lectura), `init` (aplica la política de forma idempotente) y `check` (gate de conformidad CI-ready con exit 0/1). El estándar deja de ser solo documento y pasa a ser comprobable y aplicable por máquina.

La release agrupa el trabajo del PR #40 (merge `d57de04`, 7 commits de feature + 1 de docs), el refactor del comando `funky assess` (eliminación de `architecture-review.md`) y el docs sync post-merge (doc nuevo `secure.md` en el SSOT, mención "Novedad" en el README raíz, fila en `funky-cli/README.md` y repo-map).

### ✨ Nuevas Funcionalidades y Refactor
- **[Feat] `funky secure doctor`:** diagnóstico de solo lectura del estado de hardening del repo. Detecta la versión de pnpm de forma **conductual** (`pnpm config list --json` — `config get` es ciego en pnpm v10/11 para las claves del workspace), la cuarentena conductual (`minimumReleaseAge`), instalaciones duplicadas de pnpm, y señales del repo (lockfile npm, rangos flotantes, `.env*` trackeados, baseline de hooks, marcador de AGENTS, `allowBuilds` pendiente).
- **[Feat] `funky secure init`:** aplica la política pnpm de forma idempotente: merge del seed de `pnpm-workspace.yaml` (7 claves estándar, preservando `packages:`, comentarios y valores existentes distintos como "conservado"), bloque `AGENTS.md` con marcador, baseline SHA-256 de dev hooks en `.funky/secure-state.json`, `.gitignore` append-only y pin de `packageManager`. Postura `fail-silent`/`fail-fast` (pregunta con TTY, `--posture` obligatorio sin TTY — sin él exit 1 y ninguna escritura).
- **[Feat] `funky secure check`:** gate CI-ready (exit 0 conforme / exit 1 violaciones o fail-closed) con violaciones tipadas: `missing-lockfile`, `package-lock`, `floating-ranges`, `config-mismatch`, `quarantine-inactive`, `pending-approval`, `env-tracked`, `env-unignored`, `hook-drift`, `pnpm-probe`/`git-probe`.
- **[Feat] Cross-version pnpm:** normalización del output de `pnpm config list` entre pnpm 10.x (kebab-case) y 11.x (camelCase); dedup de shims win32 (`where.exe` devuelve `pnpm` y `pnpm.CMD` del mismo install).
- **[Refactor] `funky assess`:** deprecación y eliminación de `architecture-review.md` (template y lógica del prompt); tests de integración recortados.
- **[Docs] Docs sync post-merge:** `docs/funky-ai/secure.md` nuevo (comandos, posturas, violaciones, estado local) + índice seccional + fila SSOT + fila repo-map; mención breve "Novedad: `funky secure`" en el README raíz; fila en la tabla de comandos de `funky-cli/README.md`.

### 🧠 Aprendizajes (Engram)
- `pnpm config list --json` es la única vía fiable para leer las claves de workspace YAML; `config get` es ciego para ellas.
- El output de `pnpm config list` difiere entre pnpm 10.x (kebab-case) y 11.x (camelCase): exige normalización cross-version.
- `where.exe` en win32 devuelve `pnpm` y `pnpm.CMD` para el mismo install → falsos duplicados sin dedup.
- `minimumReleaseAge` en `pnpm-workspace.yaml` bloquea dependencias <72h con `ERR_PNPM_NO_MATURE_MATCHING_VERSION`; `--frozen-lockfile` es inerte ante la cuarentena ("Already up to date").
- Vitest `forks singleFork` sin isolate filtra `vi.mock` entre archivos: los tests deben declarar sus propios mocks.
