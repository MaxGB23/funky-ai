# 🚀 Funky AI v2.1.0 Release Notes

## 🌟 Resumen de la Versión

La v2.1.0 introduce el sistema de **Protocolos On-Demand** — una forma de que el Orquestador adopte roles especializados (como el "Abogado del Diablo") para tareas de alto riesgo, sin contaminar el System Prompt global.

La filosofía central: el humano siempre controla qué contexto se inyecta y cuándo. Los protocolos son opt-in explícito, no automáticos.

---

### ✨ Cambios Principales

- **New: `.agents/protocols/`** — Directorio local de protocolos on-demand. El Orquestador los sugiere proactivamente cuando detecta riesgo en una fase. El humano decide si aplicarlos.
- **New: Protocolo `devil-advocate.md`** — Rol de auditor estricto. Analiza planes en busca de puntos de falla, casos borde omitidos y preguntas bloqueantes antes de que se escriba una línea de código.
- **New: `index.md` de protocolos** — Tabla de referencia rápida. El Orquestador la consulta para saber qué protocolos están disponibles sin leer cada archivo.
- **New: Etiquetado proactivo `[⚠️ RIESGO ALTO]` en `tasks.md`** — Los templates del ciclo SDD ahora instruyen al Orquestador a evaluar cada fase y etiquetar las de alto riesgo, sugiriendo el protocolo apropiado del `index.md`.
- **New: CLI — Selector interactivo de protocolos en `funky init`** — Al inicializar un nuevo proyecto, el CLI ahora pregunta interactivamente qué protocolos on-demand se desean importar. Solo se copian los seleccionados (opt-in selectivo).
- **New: `funky-cli/src/templates/protocols/`** — Templates de protocolos distribuibles vía CLI para nuevos repositorios.

### 🔒 Guardrails Preservados

- El modo Headless de `funky init` (Canvas ya existentes) **no fue modificado**. El selector de protocolos solo aparece en el flujo interactivo.
- Los protocolos son **100% opt-in**. Si el usuario no selecciona ninguno, nada se copia.
- La Capa 1 (Global Prompt) permanece intacta y agnóstica al repositorio.
- El Orquestador *sugiere* protocolos — nunca los activa de forma autónoma.

### 🧠 Aprendizajes (Engram)

- **`[protocols-as-opt-in-context]`** — Los protocolos especializados (roles de auditor, reviewer, etc.) tienen que ser opt-in explícito. Inyectarlos siempre en el System Prompt genera ruido y contradice el principio de contexto mínimo suficiente.
- **`[cli-library-consistency]`** — Antes de especificar una librería interactiva en un handoff, verificar qué usa el codebase existente. El CLI ya usa `@clack/prompts`; introducir `inquirer` hubiera sido una deuda técnica innecesaria.
