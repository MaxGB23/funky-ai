# 🚀 Funky AI v2.5.1 Release Notes

## 🌟 Resumen de la Versión

Esta versión marca la muerte definitiva del anti-patrón de "Disk I/O basura" que representaba el `worker-handoff.md`. Desde el inicio del framework, este archivo actuaba como mensajero físico entre el Orquestador y los Workers — un diseño que tuvo sentido como muleta inicial, pero que quedó obsoleto con la llegada de los custom workflows.

Con la v2.5.1, el Orquestador inyecta el scope y las tareas directamente en el prompt del worker (Message Passing directo), el CLI ya no ensucia los scaffoldings con ese archivo, y el `report.md` asume el rol de contrato de salida del worker por diseño.

### ✨ Refactor: Message Passing Directo

- **Deprecación de `worker-handoff.md`:** Eliminados todos los templates residuales en `.agents/templates/` y `funky-cli/src/templates/`.
- **CLI limpiado:** `init.js` y `feature.js` ya no copian ni referencian `worker-handoff.md` o `plantilla-worker-handoff.md` en ningún scaffolding.
- **Orquestador actualizado:** Gates G1, G2 y G3 del Return Statement purgados. El Orquestador ahora emite instrucciones directas al human para invocar al worker con scope y tareas en el prompt.
- **`funky-worker.md` refactorizado:** Desvinculado del handoff. Jerarquía de Conocimiento (Skills + MCP `context7`) inyectada. Return Envelope apunta al `report.md` físico como única fuente de verdad.
- **`report.md` blindado:** Inyectada regla `[SISTEMA - PARA EL WORKER]` que prohíbe sobrescritura y obliga al worker a annexar su sección respetando el historial.

### 🔒 Guardrails Preservados

- `planning-handoff.md` NO fue tocado. Su persistencia física se mantiene justificada para el flujo del Sub-Orquestador (Tier 4), donde la complejidad del contexto lo amerita.
- El flujo de `report.md` (cómo el worker reporta) no cambió estructuralmente — solo su instrucción de lectura migró del handoff al template base.

### 🧠 Aprendizajes (Engram)

- **`[worker-handoff-deprecation]`:** Message Passing directo en el prompt elimina I/O de disco y reduce acoplamiento entre fases del SDD.
- **`[brittle-tests-filecount]`:** Tests con `toHaveBeenCalledTimes(N)` hardcodeado para archivos de scaffold son frágiles ante cambios del template. Preferir tests por nombre de archivo, no por conteo.
