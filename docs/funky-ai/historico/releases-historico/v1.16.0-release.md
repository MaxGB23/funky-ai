# 🚀 Funky AI v1.16.0 Release Notes

## 🌟 Resumen de la Versión

v1.16.0 cierra el pendiente **017 — Handoff Enforcement (Agent DRY)**, una release de corrección de protocolo que resuelve un bug estructural descubierto en tiempo real: el Orquestador podía emitir el prompt de delegación al Worker sin haber generado el `worker-handoff.md`, dejando al Worker ciego.

El fix fue aplicado inline por el Orquestador — sin ciclo Worker — dado que se trata de ediciones documentales puras en un solo archivo de reglas. La sesión también produjo un debate arquitectónico valioso sobre CLI-first scaffolding como solución a largo plazo, documentado como contexto futuro para el pendiente 009.

La meta-ironía de la sesión: el pendiente existe para evitar que el Orquestador saltee pasos de protocolo, y en el proceso de planificarlo, el Orquestador salteó leer el template canónico de `tasks.md`. Eso aceleró la decisión de aplicar el mismo patrón de enforcement a `/sdd-ff` que ya existía para el handoff.

### ✨ Cambios de Protocolo

- **Return Statement bloqueante:** La sección "Protocolo de Delegación (MANDATORY)" fue reemplazada por "🔴 Return Statement — Delegación (MANDATORY — BLOCKING)" con tabla de gates G1/G2/G3. El Orquestador no puede emitir el prompt de delegación hasta que G1 (handoff existe), G2 (Tier completado) y G3 (ruta del tasks.md en §1.C) pasen.
- **Prerequisito `/sdd-ff`:** El comando `/sdd-ff` ahora requiere explícitamente `view_file funky-cli/src/templates/sdd/tasks.md` antes de generar el `sdd-tasks.md`. Mismo patrón que ya existía para el handoff.
- **Planning Checklist simplificado:** Se eliminó el ítem #2 (generación del handoff) del Planning Checklist — movido al Return Statement como gate bloqueante. Sin duplicación.

### 🛠️ Archivos Modificados

- **`.agents/rules/sdd-orchestrator.md`:** Tres cambios: Return Statement G1/G2/G3, prerequisito view_file tasks.md en `/sdd-ff`, y Planning Checklist limpiado (4 → 3 ítems).
- **`docs/engram/discoveries.md`:** Nueva entrada `[handoff-as-return-statement]`.
- **`docs/engram/index.md`:** Nueva fila en tabla Discoveries.
- **`ORCHESTRATOR-STATE.md`:** 017 marcado como completado, versión bumpeada a v1.16.0, 009 actualizado con fase futura de CLI scaffolding.
- **`docs/funky-ai/drafts/cli-sdd-scaffolding-debate.md`:** Nuevo documento con el debate completo sobre las tres opciones evaluadas (parche, CLI-first scaffolding, reducción de artefactos) y la pregunta de diseño abierta para 009.
- **`openspec/changes/017-handoff-enforcement/`:** Artefactos SDD de la sesión (explore, proposal, spec, tasks, worker-handoff). Archivados en `openspec/archive/v1.16.0-017-handoff-enforcement/`.

### 🔒 Guardrails Preservados

- El template `funky-cli/src/templates/sdd/worker-handoff.md` no fue modificado — ya era correcto.
- El template `funky-cli/src/templates/sdd/tasks.md` no fue modificado — el problema estaba upstream en las reglas, no en el template.
- Patrón Agent DRY mantenido: el Return Statement referencia el §Protocolo Obligatorio sin duplicar su contenido.

### 🧠 Aprendizajes (Engram)

- **`[handoff-as-return-statement]`:** El `worker-handoff.md` es el único Return Statement válido de la orquestación. El enforcement estructural (gate bloqueante) es más robusto que un checklist post-hoc.
- **CLI-first scaffolding (debate 009):** La opción de hacer que el CLI genere `sdd-tasks.md` desde el template es la dirección correcta a largo plazo, pero requiere que 009 resuelva primero la estrategia de templates. La tensión entre "scaffold base" y "adaptaciones post-Canvas" es la pregunta de diseño abierta.
