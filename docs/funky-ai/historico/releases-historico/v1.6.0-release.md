# Release v1.6.0 — TDD & CI/CD Pipeline

**Fecha:** 2026-04-20
**Rama:** `feat/v1.6-tdd-ci` → `main`
**Tag:** `v1.6.0`

---

## 🎯 Objetivo de la Release

Establecer una red de seguridad de calidad para el CLI de Funky AI mediante la introducción de Test-Driven Development (TDD) con Vitest y un pipeline de Integración Continua (CI) con GitHub Actions.

---

## ✨ Cambios Principales

### 1. Vitest — Motor de Testing
- Se instaló `vitest@4.1.4` (versión pineada, sin caret — SecOps compliant).
- Nuevo script `pnpm test` (`vitest run`) en `funky-cli/package.json`.
- **10 tests unitarios en verde** cubriendo los dos comandos core del CLI.

### 2. Refactor de Testabilidad — Funciones Puras
- `funky-cli/src/commands/init.js` → lógica extraída a `runInit(opts)`.
- `funky-cli/src/commands/phase.js` → lógica extraída a `runPhase(opts)`.
- La surface del CLI (`commander`) queda intacta. Los tests prueban las funciones puras, no el framework.

### 3. Suite de Tests Unitarios

| Archivo | Tests | Cobertura |
|---|---|---|
| `tests/sanity.test.js` | 1 | Validación del setup |
| `tests/init.test.js` | 4 | Happy path, skip, estado mixto, error propagation |
| `tests/phase.test.js` | 5 | Inyección, lowercase, template inexistente, overwrite guard, error |

Todos los mocks son puros (`vi.mock('fs')`, `vi.spyOn(console)`). Zero I/O real.

### 4. GitHub Actions CI Pipeline
- Archivo: `.github/workflows/ci.yml`
- Triggers: `push` y `pull_request` sobre `main`.
- Stack: `ubuntu-latest` + Node 20 + `pnpm@10.23.0` (pineado).
- Cache de dependencias via `funky-cli/pnpm-lock.yaml`.

---

## 🏗️ Decisiones Arquitectónicas

- **Extraer funciones puras > Mockear el framework:** Intentar mockear `commander` directamente falla porque está acoplado a `process.exit()`. El patrón correcto es separar la lógica de negocio del entry point CLI.
- **pnpm en CI:** El workflow usa `pnpm/action-setup@v4` con `pnpm install --frozen-lockfile`. El skill de GitHub Actions sugería `npm ci` por defecto — rechazado por SecOps.

---

## 🔒 SecOps Compliance

- `vitest` pineado en `4.1.4` (sin `^`).
- `pnpm@10.23.0` declarado como `packageManager`.
- CI usa `pnpm install --frozen-lockfile`, nunca `npm`.
