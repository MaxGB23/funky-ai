# Retrospectiva: Lo que esta jornada nos enseñó — v1.7.0 Smoke Test

> **Propósito:** Post-mortem honesto de la sesión de validación v1.7.0.  
> Una carta a nuestro yo del pasado, para que el sistema futuro no vuelva a pagar el mismo precio.

---

## El diagnóstico brutal

Durante el Smoke Test de v1.7.0, el código tenía **14/14 tests en verde**. En el laboratorio, todo era perfecto. En cuanto intentamos usarlo en el mundo real, se nos vinieron encima tres problemas en cadena que casi nos arruinan la release. Ninguno fue un error de sintaxis. Todos fueron errores de diseño de sistema.

---

## 🧠 Lección 1: Los tests prueban lo que vos les enseñaste a probar

**El error:** Escribimos tests unitarios e de integración que validaban que el código funcionaba. Ningún test validó que el código *no destruyera* el trabajo del usuario.

La función `runInit` tenía lógica que sobreescribía el `PROJECT-CANVAS.md` en modo Headless. Los tests nunca pensaron en este caso de negocio porque los tests se escribieron *después* del código, y el que los escribió (el Worker) no pensó maliciosamente.

**Lo que hay que hacer diferente:**
- Antes de escribir código, hacé una lista de las cosas que el código NO debería hacer, no solo las que sí debería. Estos son tus tests de *Sad Path* y *destructivos*.
- La pregunta que siempre tenés que hacerte es: **"¿Qué le pasa al usuario si algo ya existe?"** y **"¿Qué le pasa al usuario si algo sale mal a la mitad?"**

---

## 🔄 Lección 2: El Smoke Test no es opcional, es la única verdad

**El error:** Marcamos la v1.7.0 como lista para release basándonos únicamente en la suite de tests automatizados. No la tocamos en un entorno real hasta el final.

Si no hubiéramos hecho el Smoke Test, el bug del Canvas Overwrite habría llegado a manos de un usuario real. Y el Template Sync Drift también. Y el Incomplete Scaffolding también. Tres bombas de relojería en una sola release.

**Lo que hay que hacer diferente:**
- El Smoke Test en un entorno externo es la Definition of Done (DoD) inamovible para cualquier feature que tenga efectos en el sistema de archivos o en la UX del CLI.
- No existe "está listo para hacer merge" sin que un humano lo haya tocado con sus manos en un directorio virgen.

---

## 📦 Lección 3: El CLI vive en un universo paralelo al tuyo

**El error:** Actualizaste `secops.md`. El CLI siguió distribuyendo la versión vieja. Nadie se enteró hasta el Smoke Test.

El problema estructural es que `funky-cli/src/templates/bootstrap/` es una **copia muerta**. Cada vez que el ecosistema evoluciona y vos no sincronizás manualmente esa carpeta, el CLI se convierte en una máquina del tiempo que viaja al pasado.

**Lo que hay que hacer diferente:**
- Cualquier archivo que el CLI deba distribuir tiene que tener un mecanismo de sincronización automatizado. **Si es manual, va a fallar.** Así de simple.
- El `sync-templates.js` que creamos en esta sesión no es un lujo, es infraestructura crítica.

---

## 🤖 Lección 4: Tu yo futuro como agente también tiene límites cognitivos

**El error:** El Orquestador (yo, en este caso) armó el `worker-handoff.md` sin consultar la plantilla canónica del proyecto. La instrucción existía en el disco desde hace versiones. Simplemente me la salté porque el contexto estaba saturado.

Esto no fue malicia, fue **sobrecarga cognitiva**. Cuando un agente tiene que procesar reglas globales, el estado del proyecto, el problema técnico y las instrucciones de planificación al mismo tiempo, algo se cae.

**Lo que hay que hacer diferente:**
- Las reglas críticas de proceso deben estar donde se usan, no en archivos globales que se cargan siempre. (Principio de inyección Just-In-Time).
- El humano tiene que ser el guardián del proceso, no el agente. Si el Agente se olvida de usar la plantilla canónica, es porque el sistema no lo forzó a hacerlo. La solución es estructural, no conductual.

---

## El modelo mental que hay que internalizar

```
Tests verdes ≠ Software correcto
Software correcto = Tests verdes + Smoke Test en entorno virgen + Revisión humana de UX
```

```
Template en CLI = Snapshot del pasado
                = Se pudre con el tiempo si no hay sincronización automática
```

```
Agente sin template canónico = Agente inventando su propio protocolo
                             = Divergencia garantizada a mediano plazo
```

---

## Qué cambió en el sistema como resultado de esta jornada

| Problema | Fix Aplicado |
|----------|-------------|
| Canvas Overwrite en Headless | Guard `if (!fromHeadless)` en `runInit` + test de regresión |
| Ctrl+C con exit 0 ambiguo | `process.exit(1)` en cancelación interactiva |
| EACCES sin mensaje amigable | Try/catch con mensaje explícito en el loop de copia |
| Template Sync Drift | Script `sync-templates.js` atado a `pretest` |
| Incomplete Scaffolding | `plantilla-worker-handoff.md` incluida en `filesToCopy` |
| Agente sin plantilla canónica | CLI ahora inyecta la plantilla en cada nuevo ecosistema |
